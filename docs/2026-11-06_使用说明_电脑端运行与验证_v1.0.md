# 电脑端运行与验证

本机双击`start.cmd`，启动器构建并在后台运行仓颉服务，等本机18627端口就绪后打开浏览器。`demo.cmd`为独立样例模式，页面显著标识。`stop.cmd`只停止PID与可执行文件路径都符合本工程记录的实例。

其他Windows电脑从[官方Nightly归档](https://gitcode.com/Cangjie/nightly_build/releases/tag/1.3.0-alpha.20261106001044)取得同日Windows x64 SDK及stdx，SDK ZIP按同页`.sha256`核验。解压后在仓库根目录创建未跟踪的`local.env.ps1`，设置`CANGJIE_HOME`到包含`envsetup.ps1`的SDK目录、`STDX_HOME`到包含`dynamic/stdx`的stdx `windows_x86_64_cjnative`目录，再运行入口。

如需代理，HTTP库读取标准`HTTPS_PROXY`/`https_proxy`等环境变量；保留TLS证书校验。不需要API密钥，不在仓库填写登录凭据。本轮验证当前电脑，未声称完成第二台干净电脑安装验收。

主页编辑任意一行即可更换输入源；删除输入源后切换到首个自选并重设金额1。单位汇率始终以1为基准。缺失报价不返回0。历史曲线使用实际日期；跨天离线只回退当前区间内已有点并保留失败提示。

自动更新每分钟检查当前活跃基准是否达到1/6/12/24小时间隔，只在应用进程运行时工作。退出与休眠不保证后台执行。参考汇率供估算，不是交易报价。

`scripts/build.ps1`构建；`scripts/test.ps1`运行仓颉测试。`node --test tests/ui-model.test.mjs`运行页面状态测试；演示服务运行后`node tests/http-integration.mjs`做HTTP联调。真实探测先载入`scripts/env.ps1`，再运行`target/release/bin/main.exe --probe`，它会联网并更新`.local/live`。
