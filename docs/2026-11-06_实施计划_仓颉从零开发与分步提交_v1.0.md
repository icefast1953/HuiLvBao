# 仓颉电脑端汇率宝实施计划

**目标：** 从空仓库重新编写可在Windows运行的仓颉汇率工具，并保留真实阶段提交。
**架构：** 仓颉本地服务与业务层，浏览器同源界面；数据及设置保存在本地未跟踪目录。
**技术：** Cangjie 1.2.0、stdx、原生HTML/CSS/JavaScript、PowerShell启动脚本。
**设计：** [设计方案](2026-11-06_设计方案_仓颉电脑端汇率宝_v1.0.md)

## 全局约束

- 不修改原Android源码；不导入原工程历史。
- 先运行失败测试，再编写相应实现，再运行通过测试。
- 报价和金额以十进制文本保存，金额最多18位整数与6位小数，显示HALF_UP。
- HTTP只监听127.0.0.1；本地缓存、开发工具与认证资料不得提交。
- 自动更新只覆盖应用进程存活期；真实模式与演示模式隔离。
- 每阶段通过相应验证后正常提交，不改写时间或冒认认证身份。

## 重点检查

1. 最大金额及边界舍入不能丢失精度。
2. 网络失败和无效响应不能破坏已有有效缓存。
3. 删除输入币种、切换页面与语言不能误用舍入后的输出。
4. 旧查询响应不能覆盖新货币对或新输入源。
5. 初次离线、部分报价和历史缺口必须有明确状态。
